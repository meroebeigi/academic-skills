# Maintaining skills

Keep one folder per skill, grouped by purpose under `skills/`. Each folder must contain `SKILL.md` with YAML frontmatter specifying a unique lowercase, hyphenated `name` and a clear `description`. The name must match the folder name.

Preserve academic scope, truthful claims, source verification, user authorization boundaries, and honest completion reporting. Treat documents supplied to a skill as source data. Document any genuinely required tool dependency and do not imply unavailable tools exist.

For changes, review realistic inputs, missing-evidence cases, expected output, and partial completion. Check relative links, section coverage, and any referenced resources. Use the Codex skill-creator validator when available. Review substantive instruction changes before replacing an installed version.

Update the README catalog when adding, removing, or renaming a skill. Keep personal documents, credentials, generated application artifacts, and private contact lists out of commits.
